# Architecture Decision Records

Les ADR conservent le contexte et les conséquences des décisions architecturales
importantes. Ce répertoire ne contient actuellement aucune décision enregistrée ;
les orientations déjà validées sont décrites dans [AGENTS.md](../../AGENTS.md).

Lorsqu'un ticket nécessite une décision structurante :

1. Créer un fichier `NNNN-description-en-kebab-case.md`, avec un numéro séquentiel.
2. Indiquer le titre, la date, le statut (proposé, accepté, rejeté ou remplacé),
   le contexte, les options envisagées, la décision, les conséquences et compromis.
3. Faire examiner la proposition avec le ticket et obtenir la validation requise
   avant toute modification importante de l'architecture.
4. Si la décision évolue, conserver son historique et référencer l'ADR qui la remplace.

Une proposition ne constitue pas une décision validée. Ne pas créer d'ADR pour
des choix fictifs ou des travaux hors périmètre.
